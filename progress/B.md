## Devpost draft (P4, 2026-11-08) · numbers: double's A2/A3 Handoffs only

### Inspiration: the gap
Scam filters ask "is this message a scam?" They react once the link, the payment ask or the code request is already on screen. By then the victim is often hooked. Multi-turn scams (pig butchering, "wrong number", fake jobs, bank impersonation) are built for this: turn 1 looks harmless. Three gaps stay open: (1) **forecast, not detection**: no lead time and no honest confidence; (2) **new scams wait** for a vendor update and real traffic to train on; (3) **reach and action**: the best protection is limited to recent flagship phones, and the result is a label, not help.

### What it does
IronGuard reads a text conversation turn by turn and forecasts where it is heading: the scam family, the next stage, and how many turns are left before the "strike" (the link, money, code or gift-card ask). It reports calibrated confidence with an explicit "uncertain" band.
- **Before:** PreyNet warns early. In the browser it runs fully on-device; no message text leaves the phone.
- **During:** the Safeguard agent turns the forecast into a Safety Card: links are locked, the claimed brand, number and domain are checked against a curated directory and RDAP, a Cool-Down Shield appears on urgency, and next steps are one tap (or one reply code).
- **After:** a consented, scrubbed anonymous report goes to the reef. One sentence about a new scam starts the zero-day loop: Nemotron writes synthetic conversations, a small adapter head ("chloroplast", 82 KB) trains, and every phone downloads only that adapter.
- **Any phone:** forward a suspicious thread to our Photon iMessage number and get the forecast and Safety Card back in the same thread. Reply `1` to report, `2` for the official contact, `3` for the reasons.

### How we built it
- **Data, 100% team-made:** Nemotron generated the v1 set (1,773 conversations after near-duplicate removal; split by conversation 1,240 / 267 / 266, TEST = 133 scam, 133 benign, 59 hard negatives). Six scam families plus benign, with hard negatives such as real bank alerts and real delivery notices.
- **PreyNet ("Dragonfly"):** frozen MiniLM turn embeddings (role-prefixed) → Linear 385→128 + GELU → causal GRU → attention pooling over turns (`CstmdAttention`) → 640-d features → three heads: family (7), next stage (5), turns to strike (5). 192k parameters; trains on CPU. Per-head temperature scaling on VAL. The dragonfly mapping: internal models predict the prey's path (next stage and turns-to-strike heads); a population vector draws the family probabilities as a Trajectory Compass; CSTMD1-style lock-on keeps a warning from flickering off on one innocent-looking turn.
- **Honest operating point:** the lock threshold is the VAL 1%-false-alarm threshold (`theta_lock` 0.966). Release needs 2 consecutive THEM turns below 0.40.
- **Results (TEST, means over 3 seeds, from `make eval`):**

  | Metric | PreyNet | Best per-message baseline |
  |---|---|---|
  | Lead time (turns of warning before the ask) | **2.799 ± 0.324** | 2.113 (B3, mean MiniLM) · 1.639 (B2) |
  | Early-warning rate EWR@1 / @2 / @3 / @6 | 0.471 / 0.591 / 0.667 / 0.739 | |
  | Benign false-alarm rate (TEST) | 0.018 | |
  | Hard-negative false-alarm rate | 0.034 | |
  | Calibration error (ECE) before → after temperature | 0.072 → 0.025 | |
  | Warning flicker with lock-on vs without | 0.000 vs 0.067 | |

  We do **not** claim the attention or multi-task parts help: the ablations (no attention 2.779, no multi-task 2.649) are within one standard deviation.
- **On-device:** ONNX export (opset 17, 774 KB) matches PyTorch within 1.1e-5. The browser runs MiniLM (transformers.js) plus PreyNet (onnxruntime-web) locally.
- **Chloroplasts ("Leaf Sheep"):** a 640→32→1 adapter on the frozen PreyNet features, 82,180 bytes, trained in 1.17–1.32 s end to end on 120 + 120 conversations (benchmark). Its threshold is the 1%-FPR point on held-out hard negatives and on a bank of base negatives; it refuses to publish if it cannot reach 1%.
- **Stack:** Python 3.11 + PyTorch (`ml/`), FastAPI + SSE (`api/`), Vite + React + TypeScript (`web/`), Node + spectrum-ts (`bridge/`), Nemotron on NVIDIA Brev (vLLM) with build.nvidia.com as backup, cloudflared.
- **Team process:** three people, strict path ownership enforced by a pre-commit hook, JSON Schema contracts in `contracts/` with mocks from hour 1, so nobody waited on anybody.

### Nemotron workflows (no chat window)
1. **Algae red-team factory** (`api/ironguard_api/agent/algae.py`): plan variation knobs → generate in parallel batches → local checks (schema, stage order, no leaked label words) → a Nemotron critic drops anything below realism 4 or with a wrong label → word-shingle dedupe → validated JSONL. Nemotron's output trains a model: it is the teacher in a distillation pipeline.
2. **Safeguard agent** (`agent/safeguard.py`): an OpenAI-style tool loop of at most 6 steps over `lookup_official_contact`, `check_domain` (RDAP age + lookalike distance) and `check_number`. Code, not the model, sets confidence (= model risk), the verdict, the locked links and the reply codes. The model writes only the headline, the reasons and the step labels. Invented numbers or domains are rejected; invalid output gets one retry, then a rule-built card. Live on our stack, a card comes back in about 2 s.
3. **Zero-day loop** (`agent/zero_day.py`): one sentence → Nemotron plans 8 mutation axes → positives plus hard negatives → critic → dedupe → chloroplast training → SSE progress to the Reef Lab → phones fetch the 82 KB adapter.

### Photon
A real iMessage number (Photon Beta / spectrum-ts 12.15.0). Forward a thread; newlines become separate turns. The bridge keeps at most 20 turns per conversation in memory only and clears it after 30 minutes idle. It never logs message text. It verifies webhook signatures, ignores duplicate deliveries and its own outbound messages, and acknowledges before scoring. It calls `/v1/score`, then `/v1/agent/safety-card` when risk ≥ 0.35, and replies in the same thread with family, turns to strike, the confidence band, the reasons and reply codes `1/2/3`. The Reef Lab shows a fully masked preview of each forwarded message. Photon mode is the one opt-in cloud mode.

### Challenges
- **Synthetic data is too easy.** v1 scams already score 0.84–1.0 at turn 1 on TRAIN, which points to style differences in the generated text. On a hand-written "wrong number → crypto" chat, the shipped model gave risk 0.004. Our human-written test set (`data/test_human/`) is still empty, so the cross-generator gap is unmeasured. We report this instead of hiding it.
- **Honest metrics took discipline:** thresholds come from VAL only, a leakage-hunter agent reviewed every training change (no leakage found), and every number in the UI comes from `eval_summary.json` or shows `--`.
- **Zero-day speed:** training is about 1 s, but generating 240 good conversations with Nemotron takes minutes, not seconds.
- **Tool calling on self-hosted vLLM** needed a rule-built fallback card so users are protected even when the model call fails.
- **Three people, 12 hours, two previous merge disasters:** solved with path ownership, additive-only contracts and mocks for every service.
